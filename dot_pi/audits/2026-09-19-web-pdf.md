# Web/PDF audit — implemented 2026-09-20

Applied 26 scoped files through chezmoi; installed files match source and all
suites passed again from the installed paths. Run `/reload` in normal Pi.

Audit baseline: `1700f77`. Approved direction: improve the existing harness;
keep tools compact and processing local. Subagents/questions and `pi-lean`
exposure remain separate work.

## Decisions retained

- Free, keyless Exa; query/options reach Exa, without conversation, model identity,
  session IDs or browser cookies. No paid fallback, account or SearXNG deployment.
  Free availability/quotas can change; no free-endpoint zero-retention guarantee.
- Local HTML/PDF extraction and local browser rendering. Jina stays off by
  default and requires explicit authorization for a public, non-sensitive URL.
- Browser interaction is loaded on demand; no large browser schema in ordinary
  sessions. No new npm dependencies.

## Implemented

- [x] **Fetch:** final/requested URL provenance, resolved links, tables/code,
  short-page success, challenge/login warnings, readable/raw/render modes and
  local DOM/RSC fallback. HTML/PDF parsers run in terminable workers (15 seconds,
  256 MiB JS heap); whole fetch/fallback deadline 30 seconds.
- [x] **Artifacts:** private shared search/fetch storage; 24-hour pruning on later
  writes, 128 files / 128 MiB, 32 MiB per artifact. Limits are best-effort across
  concurrent Pi processes. Idle files need manual cleanup; copy durable work out.
- [x] **PDF fetch:** original retained for skill handoff; magic-byte detection,
  physical page markers and PDF labels, empty-text warnings, explicit ranges
  (first 20 by default, maximum 100), source coverage separate from output limits.
- [x] **PDF skill/helpers:** task-directed reading; bounded metadata/TOC, search,
  extraction and rendering; long documents read in sections; scan/search caveats
  and multi-column visual checks. Optional local OCR with language validation.
  English tessdata installed at `~/.local/share/pi-pdf/tessdata`; no document
  upload. Runtime skill reduced to 388 words; setup/tests moved to a reference.
- [x] **Browser:** disposable unauthenticated fetch rendering, separate from debug
  state; small `browser_enable` loader plus `/browser on/off`; readable snapshot;
  caller abort and deadlines close the actual context and invalidate queued work.
  Default profiles are private per-session directories, removed on shutdown or
  reload. Explicit `PI_BROWSER_PROFILE` retains cross-restart persistence.
- [x] **Search:** validated domain/publication-date/freshness options select Exa's
  keyless advanced tool. Structured results have numbered sources and filter
  mismatch warnings; unstructured provider text is preserved. Truncation saves
  recoverable output. Legacy phrase/site hints remain non-strict.

## Validation

- Search **35**, fetch **31**, PDF **11**, browser **61** regression checks passed.
  Additional artifact checks cover permissions, expiry, count eviction, concurrent
  unique writes, input/size limits and cancellation. Both skills validate.
- Real Chromium/local fixtures covered infinite loops, unresolved promises,
  cancellation, queued calls, concurrent isolated profiles and fetch rendering.
- Generated PDFs covered scans with successful English OCR, physical/printed
  labels, 120-page targeted lookup, multi-column caveats and output/render bounds.
- One live advanced Exa query returned three sources matching domain/date filters
  in ~2.7 seconds. This validates one request, not universal filter correctness or
  search-ranking quality. Freshness remains provider-controlled.
- Public Python documentation extracted ~67k characters in ~0.8 seconds; W3C's
  dummy PDF in ~0.5 seconds. The saved PDF worked directly with the local helper.

## Practical limits

Extraction is heuristic. Complex tables retain HTML; RSC is best-effort; rendered
pages get a bounded settling interval. Use interactive tools for slower/dynamic
flows. PDF text/OCR does not establish correct equations or column order: inspect
relevant page images. Other OCR languages still need local language data.
`pi-lean` continues to exclude these extensions/automatic skill discovery.
