# Web/PDF improvement tracker — 2026-09-19

Agreed direction; implementation has not started. The user is discussing design
questions before starting. Audit baseline: `1700f77`.

## Decisions

- Keep free, keyless Exa. Queries reach Exa; no conversation, model identity or
  cookies are sent by our adapter. The user accepts this compromise. No paid
  fallback, account requirement, or SearXNG deployment is planned.
- Keep extraction and PDF processing local. Hosted extraction remains explicit
  opt-in. Preserve bounded output/downloads and a small default tool surface.
- Improve the existing extensions and PDF skill incrementally. Subagents and
  ask-user tools are outside this work.

## Work, in order

- [ ] **Fetch correctness** — report requested/final URLs; resolve relative links;
  preserve tables/code; distinguish suspicious challenge/login pages from source
  content; accept useful short pages; offer local fallback/raw extraction.
  Preserve useful full artifacts with bounded retention. Review parser
  cancellation: network deadlines do not stop CPU-bound extraction.
- [ ] **PDF workflow** — retain downloaded originals in private temp storage;
  preserve page markers; report extraction range and empty-text/scan pages;
  recognize PDFs served through generic download endpoints. Connect fetch to
  the skill without redownloading. Distinguish source coverage from output
  truncation and physical page indices from printed labels.
- [ ] **PDF skill and helpers** — use task-directed extraction/rendering, bounded
  search/metadata output and render limits; support full reading in sections.
  Add optional local OCR and check language data. Validate multi-column text;
  use page images for relevant equations/tables/diagrams. Math/image heuristics
  cannot prove visual inspection is unnecessary.
- [ ] **Browser integration** — add disposable, unauthenticated rendering for
  JS-dependent reading; keep it separate from persistent interactive debugging.
  Add a tiny model-callable loader for the existing eight tools, retaining
  `/browser on/off`. Implement real cancellation and profile isolation; consider
  readable snapshots to reduce ad hoc JavaScript.
- [ ] **Search refinement** — compact domain/date/freshness controls using Exa's
  keyless advanced tool when needed; predictable source formatting and
  recoverable truncation. Verify filter behavior rather than promising strict
  semantics. Keep the backend replaceable.

Skill cleanup discussed: retain the interpreter invocation and routine usage in
`SKILL.md`; move installation/recovery and regression-test instructions into a
reference loaded only when needed. Setup is optional, not a skill-format rule.

## Evidence and acceptance checks

Existing suites passed: search **28**, fetch **20**, PDF **6**, browser **46**
(real Chromium with disposable profile/local server). Installed fetch/browser
entry files matched source. Tests establish behavior, not search-ranking or
model-comprehension superiority.

Additional probes reproduced relative links/wrong redirect provenance, flattened
tables, false short-page warnings, challenge-page success, scan-PDF empty success,
missing PDF page markers, and generic-MIME PDF rejection. Probe artifacts are
in `/tmp/pi-web-audit/` and may expire.

English OCR failed: Tesseract currently lists only `afr` and `osd` in its
configured data directory. `pi-lean` excludes web extensions and skill discovery;
changing that launcher's exposure would require a separate decision.

Validate fixes with redirected docs, tables/code, JS/challenge pages, scanned and
multi-column PDFs, theorem/page citations, long-document targeted questions,
render/eval cancellation, and browser-state separation. Measure correctness,
context size, calls and latency. No paid services or personal documents needed.

## Comparison and reference links

- [Exa MCP](https://exa.ai/docs/get-started/exa-mcp): still advertises free keyless
  access, including advanced search. No retirement announcement found. Public
  server defaults are not a guaranteed deployed quota. Its
  [privacy policy](https://exa.ai/privacy-policy) does not establish a free-endpoint
  no-training/no-retention guarantee.
- [pi-web-access](https://github.com/nicobailon/pi-web-access): useful maintained
  reference for Defuddle fallback, saved-content retrieval, passage finding and
  provider controls. Shares Readability/Turndown foundations; free local PDF
  path remains basic `unpdf`. Richer hosted PDF paths send documents externally.
- [OpenCode](https://github.com/anomalyco/opencode/tree/dev/packages/opencode/src/tool):
  useful search/fetch controls; no demonstrated wholesale quality advantage.
- [OpenRouter](https://openrouter.ai/docs/guides/features/server-tools/web-search):
  hosted, metered search with filters/citations; not a local fetch/PDF replacement.
- [PyMuPDF](https://pymupdf.readthedocs.io/en/latest/recipes-ocr.html): supports
  local Tesseract OCR; requires language data and benefits from cached OCR.
